Four levels, from fastest to most realistic.

## 2. Replay mode (recorded screenshots, no OBS)
`killsense-replay` feeds a folder of frames through the **same** capture planning and pipeline used in OBS.

```powershell
killsense-replay --profile data\profiles\sample-killfeed.json ^
                 --frames tests\data\sequences\sample-killfeed --fps 6 --verbose --expect 4
```
- Frames: `*.png|*.jpg|*.bmp`, sorted by name, timestamps = index / fps.
- `--ocr sidecar` (default) reads `frame_0001.ocr.txt` next to each frame — deterministic OCR for tests. `--ocr platform` uses Windows OCR on the real pixels. `--ocr none` disables OCR.
- `--verbose` prints per-frame confidence, active signals, decisions and processing time; `--json` prints full event JSON.
- Record your own: OBS *Screenshot (Source)* repeatedly, or extract frames from a recording with ffmpeg: `ffmpeg -i clip.mp4 -vf fps=6 frames\frame_%04d.png`.

The bundled sequence (`tests/data/sequences/sample-killfeed`, generated by `tools/assets/generate_test_assets.py`) contains: a kill with a one-frame flicker, a rapid double kill, a death message (must **not** count as a kill), and another kill. Expected: 4 kills, 1 death, best streak 3.

## 3. Headless libobs integration (real GPU capture path)
`tools/libobs-harness` starts libobs without the frontend, builds a scene from the test images and runs the real `FrameSampler` (tick callback → texrender ROI crop → staging → map) + worker, toggling the overlays like kills:
```bash
cmake -S . -B build -DKILLSENSE_BUILD_OBS_HARNESS=ON && cmake --build build
xvfb-run -a build/killsense-obs-harness . /usr/lib/x86_64-linux-gnu/obs-plugins/image-source.so /usr/share/obs/obs-plugins/image-source
```
Result on OBS 30.2 / software OpenGL: `kills after first entry: 1 (expected 1), total kills: 3 (expected 3)`, 64 samples, 0 dropped, 0 map failures.

## 4. Inside OBS — Milestone 1 acceptance procedure (Windows)

1. Install the plugin (docs/BUILDING.md) and start OBS. **Docks → KopSkoot**.
2. Build a test scene, e.g. "KillSense Test":
   - Image source `ks-bg` → `…\realm-killsense\data\test-assets\killsense-test-background.png`
   - Image source `ks-kill-row1` → `killsense-test-kill-row1.png` (**hidden**)
   - Image source `ks-kill-row2` → `killsense-test-kill-row2.png` (**hidden**)
3. In the dock: Source = `KillSense Test [scene]`, Profile = *Sample Kill Feed (test profile)*.
4. **Start Detection**. Detector state: *Running*. OCR engine should show `windows.media.ocr` (if it says unavailable, see BUILDING.md troubleshooting — the test still passes on template + colour).
5. Show `ks-kill-row1` for ~3 s ⇒ **Kills this session = 1** (exactly once, although the entry stays visible). Hide it.
6. Wait 2 s, show `ks-kill-row2` (a new entry on top + the old one below) ⇒ kills = **3** (rapid second kill counted).
7. **Test Kill Event** ⇒ kills = 4, Last event *Kill (test)*.
8. **Debug View** while an overlay is visible: region image with red template boxes, OCR text, per-signal contributions, PASS/temporal state.
9. **Reset Session** ⇒ counters 0.
10. **Settings**: change preset to Low Impact → OK; restart OBS ⇒ source, profile and preset are restored.
11. Close OBS while detection runs ⇒ log ends with `[realm-killsense] shut down cleanly` / `plugin unloaded`, no crash.

Automated version of steps 2–9 over obs-websocket (enable *Tools → WebSocket Server Settings*):
```powershell
pip install websockets
python tools\websocket\killsense_ws_test.py --assets "C:\ProgramData\obs-studio\plugins\realm-killsense\data\test-assets" --password YOUR_WS_PASSWORD
```
Expected last line: `vision kills: 3 (expected 3), session kills after test event: 4 (expected 4) -> PASS`.
